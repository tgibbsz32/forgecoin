# Contributing to ForgeCoin

Thank you for helping improve ForgeCoin. Changes that affect consensus, wallet security, privacy, or release packaging require especially careful review.

## Before opening a pull request

1. Open or join a GitHub Discussion for substantial protocol changes.
2. Build the affected targets and run relevant tests.
3. Explain the problem, resulting behavior, compatibility impact, and validation performed.
4. Keep generated binaries, wallets, blockchain databases, private keys, seeds, and credentials out of commits.
5. Preserve Monero and CryptoNote copyright and license notices in derived files.

Consensus pull requests must also document activation strategy, chain-split risk, economic impact, and how nodes, miners, pools, wallets, and exchanges will migrate.

## Reporting bugs

Use a public issue for ordinary reproducible defects. Follow [SECURITY.md](SECURITY.md) for vulnerabilities that could expose funds, private data, remote code execution, consensus failure, or network-wide denial of service.
