# ForgeCoin Security Policy

## Supported versions

Only the newest tagged ForgeCoin release should be considered for security fixes during the bootstrap stage.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting or a private repository security advisory when it is enabled. Do not open a public issue containing exploit instructions, private keys, wallet seeds, or details that would allow immediate theft, remote code execution, consensus failure, or network-wide denial of service.

If private reporting is unavailable, open a public issue that asks a maintainer to establish a private contact channel without disclosing technical details.

Include affected versions, operating system, reproducible conditions, expected impact, and a minimal proof of concept when safe. Maintainers should acknowledge a report promptly, coordinate a fix and release, and publish an advisory after users have had a reasonable opportunity to upgrade.
