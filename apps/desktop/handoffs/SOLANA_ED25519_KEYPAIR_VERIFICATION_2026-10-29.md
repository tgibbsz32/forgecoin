# Solana Ed25519 Keypair Verification — Handoff (2026-10-29)

The desktop vault now independently derives the Ed25519 public key from the first 32 bytes of a Solana CLI keypair using libsodium's `crypto_sign_seed_keypair`, and refuses import/encryption or restored vault decryption if the key does not match the last 32 bytes. Invalid/missing native library fails closed. A Windows smoke test accepted a deterministic valid seed/keypair and rejected a one-byte tamper. The complete WinForms source compiled.

**Release blocker:** This development patch uses a direct Windows P/Invoke dependency on `libsodium-26.dll`. The release packaging script does not currently include or verify it. Do not distribute until the library binary provenance, immutable version, SHA-256, architecture, license and secure DLL loading path are reviewed; then package it with the app and test a clean installation. The test computer already had a local MSYS2 copy; **that is not release assurance**. The checksum for that copy was not pinned or audited. No private production key material was used.

Other pending gates: replace CLI plaintext temporary-file wallet generation with offline in-memory mnemonic/key derivation, verify mnemonic restore/address parity, test fresh-device encrypted vault backup and password/attacker threat handling, independent cryptographic review, and ensure desktop app has no live mainnet mint/sale capability until separately authorized. The user's custody preference is encrypted desktop software wallets, separate native FRG 25-word seeds and Solana BIP39 seed phrases. No mint, public mining or token sale authorized.
